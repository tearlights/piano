# 当前项目状态

最后更新：2026-08-12

## 一句话结论

Gpiano 已进入“真实谱面可转换、可对照校正、可播放”阶段：单页图片经自托管 Audiveris 转换为 MusicXML 后，Android 已完成可恢复任务、结构校验、原谱对照、刻谱、片段试听、音高/时值/休止符/延音线校正、分支修订与备份恢复；AI 指导、派生练习版本与 MIDI 尚未形成闭环。

## 本轮实际推进

1. 从配套测试 MusicXML 完成结构摘要和 Android 原生刻谱，不修改原始 XML。
2. 通过内部小节索引与 alphaTab 主小节边界建立顶部小节选择到谱面滚动的映射。
3. 根据真实界面反馈压缩标题、选择器和状态区域，隐藏重复谱名与音轨标签，让谱面成为主要可视内容。
4. `:app:assembleDebug` 已通过，并在连接设备验证 MusicXML 加载、显示、滚动和第 2、3 小节定位。
5. 建立保留原 MusicXML DOM 的最小 `ScoreIR`、稳定事件标识、结构校验和局部音高编译器。
6. 在 Android 设备完成“选择首音 F♯4 → 改为 G4 → MusicXML 重编译 → alphaTab 重渲染 → 撤销恢复 F♯4”的闭环。
7. 增加 5 项基于真实测试 XML 的单元测试，覆盖解析、局部修改、升降号节点、错误目标与内存修订撤销。
8. Room 升级至 v7，新增 `ScoreStructure` / `ScoreRevision` 和标准 MusicXML 修订文件；v6→v7 设备升级未清除原数据。
9. 修订写入采用 XML 校验、临时文件提交、Room 事务和失败补偿；修改与撤销均通过强制结束进程后的再次打开验证。
10. `.gpiano` v2 覆盖当前全部库数据与结构化修订，包含逐文件大小和 SHA-256；设备验证 v2 往返、v1 兼容和篡改包拒绝。
11. 建立 960 PPQ 的 `PlaybackPlan`，将 ScoreIR 小节、事件、手别和速度编译为统一练习片段；真实 XML 测试增至 8 项。
12. alphaTab 升级至 1.8.3，工具链同步至 Kotlin 2.2.20、KSP2、Room 2.8.4、AGP 8.12.3、Gradle 8.13 和 compileSdk 36；该播放工作单元当时仍使用 Room schema v7。
13. 实机验证 1～2 小节 50% 循环约 8 秒且不越界到第 3 小节，暂停/继续/停止与光标同步；右手模式静音左手轨道，左手模式静音右手轨道。
14. Room 升级至 v8，加入持久 `RecognitionJob`；WorkManager 执行上传、轮询、下载和 MusicXML/ScoreIR 校验，曲谱库提供转换、取消、重试和打开草稿入口。
15. 提供独立 `omr-service/`，以 bearer token 调用 Audiveris 5.11.0；真实 2977×4208 测试页约 18 秒生成 127,544 字节 MusicXML。
16. 真机完成“导入图片 → 转换 → 待校正草稿 → 渲染 → 试听 → 音高修订 → 撤销”；修复 alphaTab 对 Audiveris 中间延音线顺序的栈溢出兼容问题。
17. `.gpiano` 升级至 v3，识别任务脱敏备份；设备完成 v3 导出/恢复、v2 恢复后再回到 v3，以及损坏包拒绝且原有 1 份谱、2 个结构、4 个修订、1 个识别任务保持不变。
18. 工作区加入真实输入页与结构化练习谱切换；原谱只用于核对，修改始终作用于可验证的 MusicXML 修订。
19. 校正编译器新增时值、附点/三连音比例、独立音符/休止符互转及相邻同音延音线修改；基于真实 XML 的 JVM 测试增至 12 项。
20. 修订工作区支持分支历史、任意旧版本切换、撤销与重做；真机在真实 OMR 谱上完成三连音四分音符→八分音符、音符→休止符、移除延音线、重渲染、撤销/重做及历史切换，最终回到 OMR 修订 0。
21. 新增本地 `ScorePracticeAnalyzer`，对选中范围生成带事件证据的三连音、节奏、连线、左右手配合、落键跨度与音高指导；15 项 JVM 测试通过。
22. 真机验证第 1 小节得到“三连音、连线、节奏”优先顺序、逐步练法及 75% 双手循环入口；从指导卡启动 alphaTab 后保持指导可读，关闭面板可见暂停/停止状态。

这些推进证明“真实单页谱面可以在 Android 上转换、对照、定位、按多类结构校正、持久保存、备份恢复并按片段练习”。它没有证明多页 OMR、AI 指导或 MIDI 跟弹已完成。

## 当前工程里程碑

建立受约束的派生练习版本：

```text
从结构化指导中的明确难点进入改编
→ 只生成白名单 EditPlan
→ 编译为独立 MusicXML 候选
→ 展示具体事件差异和音乐取舍
→ 试听、采纳、拒绝或导出
→ 原谱与校正主修订不被覆盖
```

编辑不得直接覆盖原谱或原始 OMR 修订；每项修改必须先校验再提交，并保留明确的恢复路径。

## 已知风险

1. alphaTab Android 加载适配仍依赖反射；1.8.3 已完成渲染与播放回归，但公开加载入口尚未替换该适配。
2. OMR 服务采用自托管 companion；正式部署需要 HTTPS、随机令牌、Audiveris/AGPL 合规说明及稳定运维，Debug localhost 只用于演示。
3. `.gpiano` v3 已覆盖识别任务，但尚无 ReadingState、派生版本和 MIDI 实体可供备份；这些实体新增时必须继续升级格式。
4. 结构化解析/编译/播放/兼容/指导层已有 15 项 JVM 测试，companion 有 5 项 Python 测试；迁移、备份、跨进程修订、OMR、校正、指导和播放完成设备验证，但持久化与 Compose 交互仍缺自动化覆盖。
5. 用户测试样本授权、OMR 准确率和校正成本尚无有效数据。
