# 2026-08-11：结构化乐谱工作区技术基线

## 决策与方案

- 新增结构化乐谱工作区技术方案，明确 OMR、MusicXML、ScoreIR、渲染、受约束 AI 编辑、播放和 MIDI 的职责边界。
- 新增 ADR-0008：用户可编辑成果采用 MusicXML，播放/设备数据采用 MIDI；内部模型、渲染器和播放器不得造成用户数据锁定。
- 以测试 MusicXML 完成 alphaTab 渲染技术 Spike；编辑和播放仍待后续验证。

## Debug Spike 实现

- 增加 alphaTab Android 依赖与“练习工作区”入口。
- Debug 构建从 `test-res` 直接读取测试 MusicXML，并通过 `MusicXmlSource` 预留 OMR 数据接口。
- 增加 MusicXML 结构摘要、内部小节选择和 alphaTab 原生渲染承载；绕过其 Android `load` 入口缺陷后，已在设备上验证双谱表、三连音和连线的可见刻谱与滚动；不修改 Room、备份或正式曲谱库。
- 将工作区压缩为标题、小节选择、谱面和单行状态，移除占用谱面高度的检查器；隐藏重复谱名和音轨标签。小节选择依据主小节边界滚动到对应位置，已在设备验证第 2、3 小节。

- 尚未实现编辑或播放验收。
