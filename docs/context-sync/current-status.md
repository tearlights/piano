# 当前项目状态

最后更新：2026-08-12

## 一句话结论

Gpiano 已从“本地琴谱阅读原型”进入“结构化乐谱工作区”阶段：真实 MusicXML 的 Android 刻谱和小节定位已验证，但可编辑数据模型、人工校正、播放、OMR、AI 与 MIDI 尚未形成闭环。

| --- | --- | --- | --- |

## 本轮实际推进

1. 从配套测试 MusicXML 完成结构摘要和 Android 原生刻谱，不修改原始 XML。
2. 通过内部小节索引与 alphaTab 主小节边界建立顶部小节选择到谱面滚动的映射。
3. 根据真实界面反馈压缩标题、选择器和状态区域，隐藏重复谱名与音轨标签，让谱面成为主要可视内容。
4. `:app:assembleDebug` 已通过，并在连接设备验证 MusicXML 加载、显示、滚动和第 2、3 小节定位。

这些推进证明“结构化结果可以在 Android 上进入可交互工作区”，没有证明 OMR 转换、人工校正或播放已经完成。

## 当前工程里程碑

使用测试 MusicXML 完成最小编辑闭环：

```text
MusicXML
→ ScoreIR 与稳定音符标识
→ 选择一个音符或时值
→ 修改并做结构校验
→ 生成新的 MusicXML 修订版
→ alphaTab 重渲染
→ 保存且可回退
```

实施数据持久化前必须先补齐实体关系、Room 迁移和旧 `.gpiano` 备份兼容设计。

第二周提交稿不得把 Debug MusicXML 展示写成“单页琴谱转换已完成”。

## 已知风险

1. alphaTab Android 加载适配依赖反射，版本升级有兼容风险。
2. 主导航已有工作区入口，而数据资源仅在 Debug 构建存在；发布前必须接正式数据源或隐藏入口。
3. 当前 `.gpiano` 备份覆盖范围小于产品文档目标，新数据不能直接接入旧格式。
4. 工程暂无自动化测试，关键验证主要依赖构建与单设备人工检查。
5. 用户测试样本授权、OMR 准确率和校正成本尚无有效数据。
