# Gpiano AI：长期项目上下文

最后更新：2026-08-06

## 现在是什么

Gpiano AI 是本地优先的 Android 智能钢琴学习伙伴。现有 Android Compose 应用已具备本地谱面接入、曲谱阅读、书签、文件夹、收藏、节拍器与 `.gpiano` 备份恢复等基础能力。

比赛项目的主线是将用户自有或已获授权的静态琴谱转化为可听、可看、可练、可调整、可校准的个人练习材料：

```text
授权谱面 → OMR → MusicXML/结构化乐谱 → 渲染与片段练习
                                      ├→ AI 解释与可编辑改编
                                      └→ MIDI 跟弹与基础匹配反馈
```

## 已确定决策

- 运行方式：本地优先、无账号、原始谱面默认不上传；模型调用或数据传输须明确授权并最小化。
- 乐谱链路：OMR 结果进入可校正的 MusicXML/MIDI 或内部小节模型；低置信度结果不得伪装为确定乐谱。
- 练习链路：选段、分手、慢速、循环、播放高亮与基于结构化乐谱的解释。
- 改编链路：原谱、识谱草稿和派生练习版本并存；AI 建议可预览、可编辑、可撤销、可拒绝。
- 演奏链路：通过兼容 MIDI 电钢琴获取按键事件，与目标片段匹配；首期仅覆盖音高、节奏、漏音、多音和连续性。
- 数据迁移：`.gpiano` 备份需逐步覆盖原谱、结构化乐谱、派生练习版本、学习状态与用户选择导出的演奏记录。
- 技术方向：Kotlin、Jetpack Compose、Room、DataStore、Storage Access Framework、PdfRenderer；OMR、MusicXML/MIDI、播放与 MIDI 适配通过可替换接口隔离。

## 现有实现事实

- PDF、JPG、PNG、WebP 与图片组导入；原始文件复制到应用私有目录。
- 曲谱库、重命名、收藏、文件夹、书签、页面顺序和 `.gpiano` 导入导出。
- PDF/图片阅读器按可视区域渲染，缓存当前与相邻页面，翻页期间保留上一页。
- 节拍器与本地 Room 数据。

上述能力是 AI 乐谱工作区的底座；OMR、结构化乐谱、片段播放、派生版本、AI 改编、MIDI 跟弹和匹配反馈尚处于比赛 MVP 设计与验证阶段，不能描述为已实现。

## 近期下一步

1. 完成第一周真实用户验证：收集 OMR 校正、片段播放、改编和 MIDI 跟弹反馈的需求优先级。
2. 为单页钢琴谱定义结构化乐谱工作区：输入、位置映射、人工校正、失败回退与隐私授权。
3. 在实现前补充数据模型/备份迁移与技术选型 ADR，再建立 OMR→MusicXML→播放的最小闭环。
4. 验证一台兼容 MIDI 电钢琴上的选段匹配反馈。

## 不要做

- 不建设在线曲谱库、账号体系或默认云同步。
- 不以黑盒方式覆盖原谱，不将 AI 建议或单次 MIDI 匹配伪装为唯一正确答案或全面演奏评价。
- 不在未校正或低置信度结构化乐谱上输出确定性的改编或演奏反馈。
- 不提交私人琴谱、演奏记录、密钥、证书、构建目录或 `local.properties`。
