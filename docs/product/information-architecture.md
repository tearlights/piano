# 信息架构与导航（比赛 MVP）

更新日期：2026-08-12

状态：目标信息架构。

当前可运行原型使用“曲谱库、收藏、文件夹、练习工作区、设置”五个底部入口。练习工作区不再直接读取测试 MusicXML：它由曲谱库中已完成 OMR 的结构化结果打开，并保存最近选择以支持跨进程恢复。下述导航仍是后续产品化方向，不应被误写成当前已完成的信息架构改造。

## 顶层导航

比赛 MVP 以“作品进入练习工作区”为主路径。作品资料、练习版本和设置保持轻量入口；结构化谱面、播放、AI 建议和 MIDI 跟弹在同一练习工作区内协作：

```text
作品          练习版本          设置
 │
 ├── 导入授权谱面
 ├── 原谱 / 识谱草稿
 └── 练习工作区（全屏）
       ├── 谱面与小节选区
       ├── 播放：分手 / 慢速 / 循环 / 高亮
       ├── AI：解释 / 改编建议 / 差异预览
       └── MIDI：设备连接 / 跟弹 / 反馈
```

## 页面职责

| 页面 | 核心任务 | 首要操作 |
| --- | --- | --- |
| 作品 | 管理原谱、识谱草稿与练习版本的入口 | 导入、打开练习工作区 |
| 练习版本 | 回到派生版本和最近练习上下文 | 比较版本、继续练习 |
| 设置 | 配置隐私、数据、播放与设备行为 | 授权、备份恢复、MIDI 偏好 |
| 练习工作区 | 将结构化谱面转化为练习动作 | 选区、播放、解释、改编、跟弹 |

## 关键流程

### 导入

```text
作品页点击“导入授权谱面”
  → 系统文件选择器
  → 校验格式与可读性
  → 复制至私有存储、提取元数据/缩略图
  → OMR 识别任务（可显示进度、暂停/重试）
  → 识谱草稿与人工校正
  → 创建结构化乐谱工作区
```

导入或识别失败时保留原始文件与已有资料；失败原因需可理解，并提供重试、跳过识别或继续以原谱阅读的路径。

### 阅读

```text
从作品或练习版本打开
  → 恢复上次选区、速度、播放模式和练习版本
  → 在谱面上选择小节或片段
  → 分手 / 慢速 / 循环 / 高亮播放
  → 请求 AI 解释或生成可预览改编
  → 可选连接 MIDI 电钢琴进行跟弹
  → 保存练习状态、反馈和版本变更
```

### 备份恢复

```text
设置 → 数据与备份 → 导出/导入 `.gpiano`
  → 选择目标或备份包
  → 校验空间、格式、版本与冲突
  → 明确显示结果与可恢复的失败信息
```

## 导航原则

- 练习工作区优先保持当前谱面可见；AI、播放和 MIDI 控件以按需浮层或底部面板出现。
- 原谱、识谱草稿与派生练习版本必须可区分、可比较且可恢复。
- MIDI 连接属于练习上下文，不单独占用顶层入口。
- 不建设在线曲谱库；数据传输和模型调用必须从设置或明确操作中获得授权。
