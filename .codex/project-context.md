# Gpiano：AI 长期上下文

## 现在是什么

这是一个本地优先的 Android Compose 琴谱阅读应用，已包含导入、曲谱库和阅读器实现。

## 已确定决策

- 产品优先级：看谱体验优先于 AI 功能。
- 运行方式：端侧优先，第一阶段无服务器、无账号、默认离线。
- 首批格式：PDF、JPG、PNG、WebP。
- 迁移方式：使用可版本化的 `.gpiano` 备份包，而非依赖云服务。
- 目标技术方向：Kotlin、Jetpack Compose、Room、DataStore、Storage Access Framework、PdfRenderer；在创建工程前仍需确认版本与兼容策略。

## 最近变更

- 阅读器渲染按可视区域尺寸解码/栅格化，并缓存当前与相邻页面；翻页期间保留上一页，避免白屏闪烁。左右翻页触控区为屏幕两侧各三分之一，中间三分之一用于切换功能栏显示。
- 琴谱库卡片新增重命名入口；名称仅更新本地数据库记录，不会修改已导入源文件或影响备份兼容性。
- 文件夹创建错误使用独立状态并仅在文件夹页展示；空名称会禁用“创建”按钮，避免错误提示误显示在曲谱库首页。
- 图片组导入记录使用 `application/x-gpiano-image-group`；阅读器必须通过 `Score.format() == ScoreFormat.Image` 判断图片，不能依赖 MIME 类型是否以 `image/` 开头。
- `ScoreRenderer` 对图片解码和 PDF 渲染异常返回空结果，避免错误文件或不匹配的格式导致阅读页崩溃。
- 图片组页面数据异步到达后，渲染器以页面相对路径重新触发渲染；图片导入使用系统多选媒体选择器。

## 近期下一步

1. 持续完善阅读器的加载失败提示与恢复路径。
2. 为导入、备份和阅读状态补充自动化测试。

## 不要做

- 不引入后端、登录、广告、在线曲谱库或 AI 识谱。
- 不为了“格式支持广”引入难以维护的阅读引擎。
- 不将用户内容上传或复制到仓库。
