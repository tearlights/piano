# ADR-0016：生成式乐谱指导通过显式授权的最小化 companion 请求

日期：2026-08-12  
状态：已接受

## 决策

Gpiano 的生成式问答不在 Android 客户端保存模型供应商密钥，也不上传原始图片或完整 MusicXML。App 只在用户针对当前选段点击“同意发送该选段并提问”后，将以下内容发送给自托管 `practice-ai-service`：

- 用户问题；
- 选段范围、速度与手别；
- 选段内经过校正的 ScoreIR 事件摘要；
- 本地 `ScorePracticeAnalyzer` 已产生的结构事实、证据标识与练习步骤。

companion 使用服务端环境变量配置兼容 Chat Completions JSON 协议的模型供应商。Android 只保存 companion 地址和访问令牌；令牌使用 Android Keystore 加密，模型供应商密钥只存在于 companion 进程环境中。

模型响应必须是受约束 JSON，包含回答、练习步骤、引用的小节/事件、可选试听参数，以及可选的练习版本预设。客户端验证所有引用都来自已发送选段，试听参数在支持范围内，练习版本只能映射到现有白名单 `PracticeVersionPreset`。验证失败时不展示不可信结果，也不修改任何乐谱。

## 隐私、故障与降级

- 每次发送都在界面中明确显示发送范围；配置过服务不等于授权自动上传。
- 请求失败、超时、服务未配置或模型输出无效时，本地结构分析、校正、播放、派生版本和 MIDI 跟弹继续可用。
- 模型不能直接输出或覆盖 MusicXML；“生成练习版本”仍由本地确定性编译器生成独立候选，经过差异预览、采纳或拒绝。
- 首版不保存完整问答历史，避免在尚未确定用途前扩大个人练习数据的持久化范围。

## 后果

- 新增独立 `practice-ai-service/`，与 AGPL Audiveris companion 解耦；部署方可以替换模型供应商。
- 设置页增加 AI companion 地址和令牌；Debug 允许 localhost HTTP，正式版本只允许 HTTPS。
- 生成式回答是对本地可核对事实的解释层，不替代 ScoreIR 校验和本地规则引擎。
