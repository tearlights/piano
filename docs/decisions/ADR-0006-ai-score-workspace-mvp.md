# ADR-0006：比赛 MVP 采用 AI 乐谱工作区闭环

日期：2026-08-05  
状态：已接受

## 决策

Gpiano AI 的比赛 MVP 围绕“静态琴谱 → 结构化乐谱 → 个人练习材料”建立闭环。首期面向边界清晰的单页钢琴谱，包含：

1. 将用户自有或获授权的谱面识别为可计算的音符、节拍、小节和左右手结构；
2. 以可校正草稿呈现识别结果；
3. 支持按小节选择、慢速/循环、左右手切换、播放高亮和基于选区的解释；
4. 验证一项可编辑的个人化改编能力（移调、可演奏性适配、技术化简或指法初稿，由第一周验证结果确定）。
5. 在边界清晰选段上验证 MIDI 跟弹的基础匹配反馈；其详细范围见 ADR-0007。

原始谱面与派生练习版本必须并存；建议必须可预览、可逐项采纳、可修改和可撤销。

## 原因

- 目标用户需要的不只是理解符号，还需要把一份标准谱转化为可听、可看、可练、可调整的个人练习材料。
- 结构化乐谱是片段播放、跟随高亮、解释、移调、指法建议和个体化适配共享的基础。
- 人工校正、差异预览与版本并存是音乐准确性、用户信任和版权边界的必要条件。

## 隐私与边界

- 原始琴谱默认本地保存；端侧识别优先。
- 若调用模型或服务，必须在传输前取得用户明确授权，并最小化数据传输。
- 不建设在线曲谱库，不以黑盒方式覆盖原谱，也不将 AI 定位为替代教师。
- 模型失败或置信度不足时，原有阅读、书签、节拍和本地数据能力必须保持可用。

## 后果

- 需要引入可替换的乐谱识别、MusicXML/MIDI 或内部小节模型、播放与派生版本数据模型；具体依赖选型应在实现前补充技术 ADR。
- 第一周优先验证单页识谱、片段化练习、MIDI 跟弹和个人化改编的需求排序。
