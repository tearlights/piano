# ADR-0002：以阅读器为中心的信息架构

日期：2026-07-29  
状态：已被 ADR-0006、ADR-0007 取代

> 历史说明：本 ADR 记录的是本地阅读器阶段的导航决策。当前比赛 MVP 以结构化乐谱工作区、AI 练习材料与 MIDI 演奏反馈为主线，现行信息架构见 `docs/product/information-architecture.md`。

## 决策

采用“曲谱库、收藏、文件夹、设置”四项顶层导航；阅读器作为独立沉浸式页面。节拍器由阅读器以底部抽屉调用，不设独立顶层入口。

## 原因

- 用户的核心任务是找到一份谱并连续阅读，而不是频繁操作复杂工具。
- 顶层入口过多会削弱曲谱库的可发现性。
- 节拍器通常与特定曲目、节奏和练习上下文绑定。

## 后果

阅读器必须承担节拍器、书签和显示设置的快速入口，但控制层需要自动隐藏并保持克制。
