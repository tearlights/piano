# ADR-0015：MIDI 跟弹使用统一时间轴、原始按键证据和边界化反馈

日期：2026-08-12  
状态：已接受

## 决策

Gpiano 使用 Android MIDI API 连接具有 MIDI 输出端口的 USB、BLE 或软件设备，接收 Note On/Note Off 消息。每次跟弹由用户明确选择结构化谱、修订或派生版本、小节范围、手别与速度，并复用现有 `PlaybackPlan` 作为唯一目标时间轴。

首版录制以用户第一个 Note On 为时间零点，避免把用户点击“开始”到真正落键的反应时间误判为节奏错误。目标中的同时发音允许小范围滚奏；匹配结果分为：

- 音高正确且时间在容差内；
- 音高正确但节奏偏早/偏晚；
- 错音；
- 漏音；
- 多音。

每次完成的尝试保存为 `PracticeAttempt`，原始发音保存为 `MidiPerformanceEvent`。尝试关联来源结构、基础修订及可选派生版本；结果保存汇总和事件级 JSON，界面反馈必须定位到具体小节或目标事件。

## 数据、迁移与备份

- Room 从 v9 升级到 v10，新增 `practice_attempts` 和 `midi_performance_events`。
- `.gpiano` 从 v4 升级到 v5，加入尝试、原始 MIDI 发音和反馈结果；继续读取 v1～v4。
- 恢复时验证结构、修订、派生版本、范围、统计数值、事件序号与外键；任一失配在写入前拒绝整个备份。
- 演奏数据默认只保存在本机和用户主动导出的备份中，不上传。

## 设备与恢复

- `MidiPracticeController` 监听设备增删，打开所选设备的 MIDI 输出端口，断开或异常时明确结束当前录制并保留已采集事件供用户决定是否完成。
- App 离开跟弹页面时关闭端口和设备，避免长期占用电钢琴。
- 未连接真实设备时可以使用明确标注的“屏幕测试输入”验证匹配流程；该输入不能作为真实 MIDI 设备验证证据。

## 边界

- 首期只评估量化目标范围内的音高、起音节奏、漏音、多音和连续性。
- 不评判踏板、力度表达、音色、手型、自由速度或艺术处理；界面不展示单一的“演奏水平总分”。
- 未校正的谱面错误会污染匹配，结果页必须保留返回原谱校正的路径。
