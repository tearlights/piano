# Gpiano AI：长期项目上下文

最后更新：2026-08-12

## 现在是什么

Gpiano AI 是面向钢琴学习者的本地优先 Android 练习伙伴。它希望把学习者自有或已获授权的静态琴谱，转化为可渲染、可播放、可理解、可编辑并可与真实演奏对齐的个人练习材料。

```text
授权谱面 → OMR → MusicXML / ScoreIR → 结构化谱面工作区
                                      ├→ 片段播放与谱面解释
                                      ├→ 可编辑的派生练习版本
                                      └→ MIDI 跟弹与基础匹配反馈
```

直接用户是处于不同练琴阶段的钢琴学习者。教师或专业人员可以参与内容和方案校验，但当前不建设独立教师端、琴行端或机构工作流。

## 已确定决策

- 本地优先、无账号；原始谱面和演奏数据默认不上传。模型调用或数据传输须明确授权并最小化。
- MusicXML 4.0 是用户可带走的记谱主交换格式；MIDI 文件与消息用于播放、设备通信和演奏事件。
- 原谱、OMR 草稿、用户/AI 修订版并存；低置信度结果不能伪装为确定乐谱。
- 内部 `ScoreIR` 负责稳定标识、编辑、校验、播放和版本关系，但不得成为无法导出的私有孤岛。
- AI 返回受约束、可校验的编辑计划，不直接覆盖原谱；建议必须可预览、修改、撤销和拒绝。
- MIDI 首期只做边界清晰片段的音高、节奏、漏音、多音和连续性反馈，不扩展为全面演奏评分。
- 现有 Kotlin、Jetpack Compose、Room、Storage Access Framework 和 PdfRenderer 作为 Android 基础；DataStore 属于偏好持久化的计划能力，OMR、刻谱、播放、AI 和 MIDI 通过接口隔离。

## 当前实现事实

### 本地琴谱底座

- 已实现 PDF、JPG、PNG、WebP 和图片组导入，文件复制到 App 私有目录。
- 已实现曲谱搜索、重命名、收藏、文件夹创建与归属、书签、页面顺序和删除。
- 阅读器按可视尺寸渲染 PDF/图片并预取下一页；支持翻页、隐藏控件和基础节拍器。
- Room 数据库当前版本为 8，已有 `Score`、`ScorePage`、`Bookmark`、`Folder`、`ScoreStructure`、`ScoreRevision`、`RecognitionJob` 及 1→8 完整迁移链；真机在不清数据情况下完成 v7→v8 升级。
- `.gpiano` v3 已覆盖当前存在的曲谱元数据、原始文件/图片页、收藏、文件夹、书签、页面顺序、结构化修订和脱敏后的识别任务；每个数据文件带大小与 SHA-256 清单，v1/v2 继续可导入。远端任务 ID和 OMR 令牌不会进入备份。

### 结构化乐谱工作区

- 底部导航已有“练习工作区”入口；正式入口来自曲谱库中已完成的识别任务，不再默认展示 Debug 测试谱。
- `MusicXmlScoreParser` 已将完整测试 MusicXML 投影为最小 `ScoreIR`，包含稳定的声部、小节、音符标识，以及声部、手别、声部内时间、时值、音高、休止、和弦、三连音、连音线和圆滑线状态。
- 原始 MusicXML DOM 仍是无损载体；当前编译器只局部修改明确选中的音高、时值、音符/休止符或相邻同音延音线，不会用不完整 `ScoreIR` 重写整份乐谱。
- alphaTab 1.8.3 已在 Android 设备渲染测试 MusicXML 的双谱表、和弦、调号、拍号、三连音和连线。
- 工作区采用紧凑布局；顶部小节选择依据 alphaTab 主小节边界滚动到对应谱面位置，第 2、3 小节已完成设备复测。
- 工作区可在真实输入页与结构化练习谱间切换，并能选择小节内事件，修改音名/升降号/八度、常用及附点/三连音时值、独立音符/休止符和延音线，再校验、编译与重新刻谱。
- `StructuredScoreRepository` 将原始与后续 MusicXML 修订写入私有目录，Room 保存当前指针与父修订关系。工作区可浏览全部历史、切换任意修订、撤销和重做；从旧版本继续修改会建立分支而不删除原修订。
- alphaTab Android 通用 `load` 入口存在类型分支问题；当前通过隔离的 `ScoreLoader`→`renderScore` 适配加载原始 MusicXML。
- `PlaybackPlan` 使用 960 PPQ 将 ScoreIR 小节、事件、速度、循环和手别投影为统一时间轴；alphaTab 使用同一加载结果合成声音、显示范围与驱动光标。
- 设备已验证 1～2 小节 50% 循环约 8 秒且不进入第 3 小节；暂停、继续、停止、双手、仅右手与仅左手均可用。
- `ScorePracticeAnalyzer` 已在选中小节范围内分析三连音、时值关系、延音线/圆滑线、调号与变化音、左右手共同落点、和弦跨度和同手跳进；每张指导卡都包含小节/事件证据、三步练法和可直接执行的速度/分手/循环试听配置。
- 指导首版在本地确定性生成，不上传琴谱，也不冒充生成式模型结果；后续模型只能基于这些可核对事实解释、排序或回应用户问题。
- `omr-service/` 已提供带 bearer token 的自托管 Audiveris companion；真机通过 Debug localhost 与 `adb reverse` 上传测试页，Audiveris 5.11.0 在约 18 秒内生成 127,544 字节 MusicXML，Android 随后完成校验、持久化、渲染、试听、修订与撤销。
- `RecognitionJob` 与 WorkManager 覆盖等待、上传、识别、失败、重试、取消和完成；Debug localhost 不依赖 Android 网络状态，正式 HTTPS 任务仍要求已连接网络。
- Audiveris 对中间延音音符输出的合法 `start, stop` 顺序会触发 alphaTab 1.8.3 自环缺陷；导入边界现以语义等价的 `stop, start` 规范化，并对旧修订读取时同样保护。
- 基于真实测试 XML 的解析、音高/时值/休止符/延音线局部编译、错误目标保护、撤销、播放计划与 MusicXML 兼容规范化共有 12 项 JVM 单元测试；companion 另有 5 项 Python 测试。
- Android 工具链当前为 Kotlin 2.2.20、KSP 2.2.20-2.0.4、AGP 8.12.3、Gradle 8.13、compileSdk 36；Room 2.8.4，数据库与 schema 为 v8。

### 尚未实现

- 小节/事件到原图的可验证像素位置映射和多页/PDF OMR；整页原谱对照已可用。
- 左右手归属、拍号、调号、和弦增删等更完整的人工校正。
- 播放片段的持久预设、预备拍、节拍器联动和自动化仪器测试。
- 用户自由提问与生成式模型解释；本地可追溯练习指导首版已完成。
- 派生练习版本、差异预览、AI 改编、MIDI 设备接入和演奏匹配。
- 仪器自动化测试和发布部署所需的 companion 运维包装。

## 当前工程顺序

1. 建立派生练习版本、差异预览、采纳/拒绝和 MusicXML 导出。
2. 复用 `PlaybackPlan` 时间轴接入 MIDI 跟弹，避免建立不兼容的匹配模型。
3. 接入可授权的生成式解释服务，让模型只消费最小化 ScoreIR 摘要与本地证据。
4. 贯通转换、校正、指导、派生版本、试听与跟弹，并补齐恢复和设备验收。

## 第二周交付差距

第二周对外交付要求是可体验的“单页琴谱转换 → 结构化草稿 → 人工校正”。当前已完成真实单页图片到待校正结构化草稿的技术闭环，并能对照原页、定位、试听、修改音高/时值/休止符/延音线、保存、浏览分支修订、撤销与重做。小节级原图映射和两位学习者真实体验仍未完成，因此只能标记为“核心技术版本已运行，用户验证未完成”。

已有一条真实界面反馈：谱面有效显示区域过少、小节选择缺乏明显作用。已据此压缩辅助区域并让小节选择滚动定位。完整流程仍需至少两位目标学习者体验；现阶段没有可提交的完整用户验证结论。

## 当前风险与约束

- alphaTab 适配仍使用反射构造 `Uint8Array`；1.8.3 已完成测试 XML 与真实 OMR 输出回归，后续仍应替换为稳定公开入口并补适配器自动化测试。
- `.gpiano` 恢复已使用临时校验、文件回滚和 Room 单事务写入；v3 已纳入识别任务，后续新增练习/MIDI 实体仍须同步升级格式。
- Audiveris 结果目前只有“待校正”状态，没有伪造整页置信度；原像素位置映射必须等 `.omr`/annotation 适配器能提供可验证坐标后再加入。
- 测试样本的授权状态须在作为比赛证据或发布资源前确认；私人曲谱和截图不得进入仓库。
- 当前有结构化 XML 编译单元测试和迁移/备份/跨进程设备验证，但尚无对应自动化仪器测试。

## 不要做

- 不建设在线曲谱库、账号体系、独立教师端或默认云同步。
- 不用手工假谱、静态占位或临时渲染结果替代真实 MusicXML 工作区。
- 不以黑盒方式覆盖原谱，不把 AI 建议或单次 MIDI 匹配包装为唯一正确答案。
- 不在未校正或低置信度结构化乐谱上输出确定性改编或演奏反馈。
- 不提交私人琴谱、演奏记录、密钥、证书、构建目录或 `local.properties`。
