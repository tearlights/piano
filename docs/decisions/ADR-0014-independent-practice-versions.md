# ADR-0014：派生练习版本使用独立候选与受约束 EditPlan

日期：2026-08-12  
状态：已接受

## 决策

个人化练习版本不写入或切换主结构化乐谱的 `currentRevisionId`。每个候选保存为独立 `PracticeVersion`，并固定关联：

- 来源 `ScoreStructure`；
- 生成时的 `baseRevisionId`；
- 明确的小节范围与预设目的；
- 白名单 `EditPlan`；
- 独立 MusicXML 文件；
- 事件级差异与音乐取舍说明；
- `draft`、`accepted` 或 `rejected` 状态。

首版白名单只包含可由确定性编译器验证的两类方案：

1. 分手练习版：保留一只手，将另一只手改为保持时间轴且可见的休止，便于看清进入位置；
2. 降低跨距版：保留右手高音/左手低音锚点，减少过密或跨度过大的和弦，并只用八度等价移动压缩过大跳进。

用户在差异预览后才能采纳；采纳只是把候选标为可使用版本，不覆盖原谱或校正主修订。候选始终可以试听、拒绝或导出为标准 MusicXML。

## 原因

- 练习化简是一种有音乐取舍的派生材料，不等同于修正 OMR 错误。
- 主谱修订历史必须继续表示“用户认为正确的结构”，不能混入尚未确认的算法改编。
- 独立候选允许用户并排保留多种练法，并能明确审阅删音、移位等变化。
- MusicXML 仍是可带走的主交换格式，避免派生版本成为 App 内私有孤岛。

## 数据与恢复

- Room 从 v8 升级到 v9，新增 `practice_versions`，不修改旧实体。
- `.gpiano` 从 v3 升级到 v4，加入派生版本元数据和候选 MusicXML；继续读取 v1～v3。
- 候选文件使用临时文件、校验、原子提交与数据库事务；失败不得改变主谱或已有候选。
- 恢复时校验来源结构、基础修订、状态、路径和候选 MusicXML，任一不一致则在写入前拒绝整个备份。

## 后果与边界

- 首版不是完整制谱或自动改编系统，不做不可验证的自由文本改谱。
- “降低跨距”会改变织体或音区，必须在差异里逐项说明，并由学习者决定是否采纳。
- 后续生成式模型可以提出 EditPlan，但不能直接返回覆盖主谱的 MusicXML。
