# Gpiano AI：长期项目上下文

最后更新：2026-08-23

## 项目是什么

Gpiano AI 是面向钢琴学习者的本地优先 Android 练习伙伴。它将学习者自有或已获授权的静态琴谱，转化为可渲染、可播放、可理解、可编辑、可导出并可与演奏事件比对的个人练习材料。

```text
授权谱面 → OMR → MusicXML / ScoreIR → 结构化乐谱工作区
                                      ├→ 片段播放与本地/AI 练习指导
                                      ├→ 可编辑的派生练习版本
                                      └→ MIDI 跟弹与基础反馈
```

直接用户是不同阶段的钢琴学习者；不建设独立教师端、机构端、曲谱商城、账号体系或默认云同步。

## 已确定技术与产品决策

- 原始谱面、结构化主谱、派生练习版本、演奏记录默认本地保存；任何 AI 外发都需逐次、显式授权并最小化传输。
- MusicXML 4.0 是记谱主交换格式；标准 MIDI 文件与 MIDI 消息负责播放、设备通信和演奏事件。
- `ScoreIR` 仅是内部稳定标识、校验、编辑与播放模型，不能成为用户无法导出的私有格式。
- 原谱、OMR 草稿、用户主谱修订和派生版本并存；AI 不能直接覆盖 MusicXML 或主谱。
- 播放、MIDI 匹配和 MIDI 导出复用同一个 `PlaybackPlan` 时间轴，避免各模块各算一套时值。
- MIDI 首期只反馈音高、起音节奏、漏音、错音、多音和连续性，不做全面演奏评级。物理电钢琴验证是进阶兼容性工作。

## 当前实现快照

- Android：Kotlin、Jetpack Compose、Room、WorkManager、Storage Access Framework、PdfRenderer、alphaTab 1.8.3。
- OMR：自托管 `omr-service` + Audiveris 5.11.0，Android 使用加密 token 和可恢复 `RecognitionJob`。
- AI：`practice-ai-service` 是独立的、自托管、兼容 Chat Completions JSON 的服务；模型密钥只在服务端环境变量，Android token 使用 Android Keystore 加密。
- 后端启动：`scripts/start-backend.sh` 统一准备/定位 Audiveris、启动 OMR 与 AI companion、验证健康状态并为单台 Android 设备建立 `adb reverse`；模型 Key 和本机令牌只放在 Git 忽略的 `scripts/backend.local.sh`。
- 数据：Room v11；除原有实体外，`PracticeVersionRevision` 为每个派生版本保存独立修订链，`PracticeVersion.currentRevisionId` 为空时指向基础候选。
- 备份：`.gpiano` v6，兼容 v1～v5，包含主谱/派生版及派生修订 MusicXML、识别任务（脱敏）、跟弹尝试与原始 MIDI 事件。
- 互操作：主谱与派生版可导出 MusicXML；当前选段可导出标准 SMF format 0 MIDI。
- 工作区选择以 `WorkspaceSelectionStore` 同步保存；强制结束进程后能重新打开最近选择的结构化乐谱。

## 已实现用户可见能力

1. 本地导入 PDF/JPG/PNG/WebP 或图片组，曲谱库管理、阅读、收藏、文件夹、书签、页序和基础备份。
2. 单页图片 OMR、失败/重试/取消/恢复、原谱与结构化谱切换。
3. MusicXML 刻谱、小节定位、片段范围、变速、循环、分手播放、光标。
4. 音高、时值、附点/三连音、音符/休止符、延音线校正；分支历史、撤销/重做。
5. 本地可追溯指导：结构证据、解释、三步练法和一键试听。
6. 授权 AI 问答：可看见发送范围，模型回答必须引用当前选段内事件；可建议试听参数和白名单练习版本。
7. 派生版本：右手/左手分手、降低跨距候选；差异预览、试听、采纳、拒绝、MusicXML 导出；候选内确定性校正、独立历史、撤销与重做。
8. MIDI：设备扫描/连接接口、屏幕测试输入、匹配与具体位置反馈、尝试记录、MIDI 文件导出。

## 当前缺口

- 单页 OMR 没有小节/事件像素映射；不支持多页/PDF OMR。
- 主谱校正尚缺左右手、调号、拍号、和弦结构等编辑。
- 没有真实学习者的完整流程验证、真实模型质量评估或真实 MIDI 电钢琴兼容性数据。
- 缺少 Compose/设备自动化测试与发布级 companion 运维包装。

## 不要做

- 不以静态假谱、占位渲染或未校验模型结果替代真实 MusicXML 工作区。
- 不让 AI 或派生版本覆盖主谱；不将 MIDI 屏幕测试称为真实设备验证。
- 不默认上传原谱、演奏记录、私钥或授权不明琴谱。
- 不在没有学习者验证前扩张到曲库、课程、教师端或全面打分。
